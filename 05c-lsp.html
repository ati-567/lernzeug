L: Liskov Substitution Principle

Ersatz muss sich wie das Original verhalten

Wichtigkeit: ★★★☆☆ Mittel wichtig (4. von 5 in der Lernreihenfolge)
Einsteiger verletzen es selten bewusst, aber wenn, entstehen schwer zu findende Fehler. Wichtig für Vererbung und eigene Fakes im Test.
Alltag: Du mietest ein Auto. Egal ob VW oder Opel: Lenkrad, Gas und Bremse müssen gleich funktionieren. Ein "Auto" ohne Bremse wäre ein Betrug.
Regel: Wo ein Interface oder eine Basisklasse erwartet wird, muss jede Implementierung einsetzbar sein, ohne dass der Aufrufer etwas merkt und ohne dass etwas kaputtgeht.

Beispiel

Verstößt 
class KaputtMailService : IMailService
{
    public void SendeBestaetigung(Bestellung b)
    {
        throw new NotImplementedException();
    }
}
Der Service verspricht Mails, tut aber nichts oder explodiert.
Passt 
class FakeMailService : IMailService
{
    public Bestellung ZuletztGesendet;
    public void SendeBestaetigung(Bestellung b)
        => ZuletztGesendet = b;
}
Verhält sich im Rahmen des Vertrags korrekt. Der Aufrufer merkt keinen Unterschied.

Woran erkenne ich es?

Wirft eine Implementierung NotImplementedException, ignoriert sie Eingaben oder prüft der Aufrufer mit is/as, um Sonderfälle zu behandeln? Dann stimmt etwas nicht.
