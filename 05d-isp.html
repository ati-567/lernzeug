I: Interface Segregation Principle

Kleine, passende Interfaces

Wichtigkeit: ★★☆☆☆ Gut zu wissen (5. von 5 in der Lernreihenfolge)
Folgt meist von allein, wenn man SRP beachtet. Wird erst bei großen Interfaces ein echtes Thema. Für den Einstieg reicht: Interfaces klein halten.
Alltag: Eine Fernbedienung mit 80 Tasten, von denen du 3 benutzt. Besser: eine mit den Tasten, die du brauchst.
Regel: Lieber mehrere kleine, passende Interfaces als ein großes. Niemand soll Methoden implementieren müssen, die er nicht braucht.

Beispiel

Verstößt 
interface IBenachrichtigung
{
    void SendeMail(...);
    void SendeSms(...);
    void SendePush(...);
    void SendeBrief(...);
}
Wer nur Mail kann, muss trotzdem alles implementieren.
Passt 
interface IMailService
{
    void SendeBestaetigung(...);
}
interface ISmsService
{
    void Sende(...);
}
Jeder implementiert und nutzt nur, was er wirklich braucht.

Woran erkenne ich es?

Gibt es Implementierungen mit leeren Methoden oder NotImplementedException, nur weil das Interface zu groß ist?
