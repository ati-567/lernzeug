2. MVC: Model, View, Controller

Alltag: Im Restaurant: Die Speisekarte (View) zeigt Gerichte, die Küche (Model) hat die Zutaten, der Kellner (Controller) nimmt die Bestellung auf und vermittelt.
Merksatz: Anzeige, Daten und Ablauf sind drei getrennte Rollen.

Idee: Wir teilen den Code in drei Rollen, damit jede Rolle nur eine Aufgabe hat.

Model
Die Daten (und ihre Regeln). Beispiel: Bestellung mit Email, Menge, Summe.
Bei uns: C#-Klasse im Backend
View
Die Anzeige. Beispiel: Bestellformular und Bestätigung. Enthält keine Geschäftslogik.
Bei uns: React im Frontend
Controller
Der Vermittler. Nimmt die Anfrage entgegen, steuert den Ablauf und liefert das Ergebnis zurück.
Bei uns: ASP.NET-Controller im Backend

Bei uns: Backend und Frontend getrennt

Im klassischen MVC läuft alles in einer Anwendung, und die View ist eine HTML-Vorlage auf dem Server. Bei uns sind zwei getrennte Anwendungen im Spiel. Das Prinzip bleibt gleich, nur die View wohnt woanders.

Frontend (React)
View
Formular, Anzeige, Fehlermeldungen. Läuft im Browser.
Backend (ASP.NET)
Controller + Model
Nimmt Anfragen an, arbeitet mit den Daten. Läuft auf dem Server.
View
React
→ HTTP/JSON →
Controller
ASP.NET
→
Model
C#

Der Ablauf

  1. Der Benutzer füllt das Formular in React aus und klickt "Bestellen".
  2. React schickt die Daten als JSON an das Backend: POST /api/bestellungen.
  3. Der Controller nimmt die Anfrage an.
  4. Er arbeitet mit dem Model (Daten prüfen, erzeugen, speichern).
  5. Er schickt das Ergebnis als JSON zurück (kein HTML).
  6. React zeigt das Ergebnis an ("Danke! Summe: 90 €").

Unser Beispiel, aufgeteilt

Model (Backend, C#) 
public class Bestellung
{
    public string Email { get; set; }
    public int Menge { get; set; }
    public decimal Summe { get; set; }
}
View (Frontend, React) 
function BestellFormular() {
  const [summe, setSumme] = useState(null);

  async function absenden(daten) {
    const res = await fetch("/api/bestellungen", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(daten),
    });
    const bestellung = await res.json();
    setSumme(bestellung.summe);
  }

  if (summe !== null)
    return <p>Danke! Summe: {summe} €</p>;

  return <Formular onSubmit={absenden} />;
}
Controller (Backend, C#) 
[ApiController]
[Route("api/bestellungen")]
public class BestellungController : ControllerBase
{
    [HttpPost]
    public IActionResult Anlegen(Bestellung b)
    {
        if (!Valide(b))
            return BadRequest("Ungültige Eingabe");

        // ... Rabatt, DB, Mail ...

        return Ok(b);
    }
}
Gewonnen: Kein HTML mehr im C#-Code. Frontend und Backend können von verschiedenen Personen entwickelt, getestet und deployt werden. Dasselbe Backend kann eine zweite App (z. B. mobil) bedienen.
Neues Problem: Der Controller hat immer noch Rabatt, Datenbank und Mail in "// ... Rabatt, DB, Mail ...". Er wird zum "Fat Controller".

Faustregeln

Gehört in …Gehört nicht in …
Controller: Anfrage prüfen, weiterleiten, passende Antwort (200, 400, 404) zurückgebenController: Berechnungen, SQL, Mailversand
View (React): Darstellung, Formulare, Anzeige von FehlernView (React): Geschäftsregeln wie "ab 10 Stück 10 % Rabatt". Der Server muss sie prüfen, sonst kann man sie umgehen.
Model: Daten und einfache RegelnModel: HTTP-Details, UI-Texte
Hinweis: Man hört auch "MVVM" oder "komponentenbasiert" für React. Für den Einstieg reicht: Backend = Model + Controller, Frontend = View. Die Idee der Trennung bleibt dieselbe.
