S: Single Responsibility Principle

Eine Klasse, ein Grund zur Änderung

Wichtigkeit: ★★★★★ Sehr wichtig (1. von 5 in der Lernreihenfolge)
Das ist das Prinzip, das du jeden Tag anwendest. Fast jeder Code-Review-Kommentar "das gehört woanders hin" ist ein SRP-Thema. Wer nur ein Prinzip lernt, lernt dieses.
Alltag: Ein Schweizer Taschenmesser kann alles, aber nichts richtig gut. In der Küche hat jedes Werkzeug eine Aufgabe.
Regel: Eine Klasse soll nur einen Grund haben, sich zu ändern.

Beispiel

Verstößt 
class BestellService
{
    void Anlegen(...)   { }
    decimal Rabatt(...) { }
    void SendeMail(...) { }
    void SchreibeSql(...) { }
}
Ändert sich Rabatt, Mail oder DB, muss dieselbe Klasse angefasst werden.
Passt 
class BestellService    { }
class RabattService     { }
class MailService       { }
class BestellRepository { }
Jede Änderung hat genau einen Ort.

Woran erkenne ich es?

Kannst du die Aufgabe der Klasse in einem Satz ohne "und" beschreiben? Wenn nicht, macht sie vermutlich zu viel.
